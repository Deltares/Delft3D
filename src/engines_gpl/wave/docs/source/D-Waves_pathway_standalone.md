# Standalone D-Waves communication model

In standalone mode, D-Waves runs without a live Delft3D4 or D-Flow FM engine.
It can read saved Delft3D4 or D-Flow FM fields, write wave fields onto the
Delft3D4 or D-Flow FM grid, or do both.

\dotfile dwaves_pathway_standalone_detailed.dot "Standalone communication model"

[DOT source](../include/dwaves_pathway_standalone_detailed.dot)

## Participants and channels

| Participant / resource | Responsibility |
|---|---|
| D-Waves manager | Select times, prepare inputs, invoke SWAN, collect and write results. |
| SWAN | Solve waves for each configured grid; exchange staged input/output files with D-Waves, including in library mode. |
| Optional existing Delft3D4 or D-Flow FM com-files | Supply saved geometry and selected hydrodynamic fields. Accept wave fields only with `WriteCOM`. |
| Boundary, forcing and D-Waves output files | Supply independent forcing and store configured wave results. |

Reading hydrodynamic fields and writing wave fields are independent choices.
In both routes below, D-Waves reads com-files produced by an earlier
hydrodynamic run. There is no live handshake and no feedback to a running
Delft3D4 or D-Flow FM engine, so this is not online coupling. If
`[Output] WriteCOM` is enabled, D-Waves writes wave fields to the com-files as
an offline file operation.

## Calculation cycle and grids

1. Read the configuration and the SWAN grids. If hydrodynamic input or output
   on the Delft3D4 or D-Flow FM grid is requested, read the existing geometry
   and prepare both mapping directions.
2. For each selected calculation time, visit the SWAN grids in the configured
   order. Prepare the inputs, run SWAN, read the results and accumulate any
   output on the Delft3D4 or D-Flow FM grid. Nested domains use the boundary
   files generated by their parent grid.
3. After the grid loop, write the accumulated wave fields to the com-files if
   `WriteCOM` is enabled; the configured D-Waves outputs are also produced.
4. Continue with the next selected time, then finalize.

The two routes below are both standalone input routes. The MDW keyword
`[Output] COMFile` selects the route (blank: Delft3D4 NEFIS com-files; set:
D-Flow FM NetCDF com-file), and with it the format of the existing com-files
that D-Waves reads. The route also affects how the calculation times are chosen
(see `wave_master_step`,
[wave_main.f90](../../packages/manager/src/wave_main.f90#L405)).

In the text below, "step size" is the `stepsize` argument of `wave_main_step`
and `wave_master_step`, not an MDW keyword. The MDW `[General] TimeStep` and
`TimeInterval` are unrelated to it: they are only read for
`SimMode = non-stationary` and are written into the SWAN input
([swan_input.f90](../../packages/data/src/swan_input.f90#L901)).

- **Existing Delft3D4 NEFIS com-files** (`[General] FlowFile` blank; existing
  runids supplied by `[General] ComFile`, or the D-Waves runid):
  `wave_master_step` calls `swan_tot` once
  ([wave_main.f90](../../packages/manager/src/wave_main.f90#L489)), and
  `swan_tot` loops over all `[Timepoint]` values in the MDW
  ([swan_tot.f90](../../packages/manager/src/swan_tot.f90#L106)). The
  `[Timepoint]` `Time` values are read into `timwav` in
  [`read_keyw_mdw`](../../packages/data/src/swan_input.f90#L1076). The
  `stepsize` argument is not used on this route.
- **Existing D-Flow FM NetCDF com-files** (`[Output] COMFile` set to the
  existing `*_com.nc` file): the `stepsize` argument matters. Each call covers
  the interval from the current time to the current time plus `stepsize`. If
  the MDW lists `[Timepoint]` values, `wave_master_step` computes only those
  inside that interval
  ([interval end](../../packages/manager/src/wave_main.f90#L502),
  [time selection and call](../../packages/manager/src/wave_main.f90#L512)).
  The `Time` values are read into `timwav` by
  [`read_keyw_mdw`](../../packages/data/src/swan_input.f90#L1076), as on the
  Delft3D4 route. If the MDW lists no times, the standalone branch makes one
  calculation at the end of the interval
  ([wave_main.f90](../../packages/manager/src/wave_main.f90#L491)).

The standalone executable always calls `wave_main_step(-1)`
([wave_exe.f90](../../packages/wave/src/wave_exe.f90#L104)). The value is fixed
in the code and cannot be set from the MDW. On the Delft3D4 com-file route it
is ignored, and all MDW `[Timepoint]` values are processed. On the D-Flow FM
com-file route the code treats it as `stepsize`, so the calculation interval
ends before the current time. **This does not mean "run all MDW times."** For
the usual non-negative MDW times, the interval contains no `[Timepoint]`
values, so the standalone executable appears to do no calculation on this
route. This conclusion is based on code reading by Copilot and has not been
verified by running the executable.

| Saved-data route | Configuration | Runtime remapping |
|---|---|---|
| Delft3D4 NEFIS com-files | Mode 0; leave `[General] FlowFile` blank. `[General] ComFile` identifies runids, or the D-Waves runid is used. | `grmap` applies internal interpolation tables in both directions. |
| D-Flow FM NetCDF com-files | `[Output] COMFile` identifies the existing communication file and partition variants. An arbitrary D-Flow FM map file is not a substitute. | D-Flow FM→SWAN uses `grmap_esmf`; SWAN→D-Flow FM uses `grmap`. |

Weights are prepared once per grid pair per initialization and reused. Both
directional maps are built when Delft3D4 or D-Flow FM grids exist, even in
read-only use; **applying** the reverse map and writing wave fields require
`WriteCOM`.

External meteo is a separate optional forcing source. When the MDW lists one or
more `meteofile` entries (in `[General]` or in a `[Domain]`) and the same domain
also requests wind from the com-file (`FlowWind` > 0), the meteo-file wind takes
precedence. The input parser resets that domain's `FlowWind` selection to 0, so
the wind from the Delft3D4 or D-Flow FM com-file is not read
([swan_input.f90](../../packages/data/src/swan_input.f90#L2052)). This applies
to `meteofile` entries only; a plain `extforce` entry does not trigger the
override.

The resulting selection is used at run time: the com-file wind is read only if
the selection is above 0
([get_flow_fields.f90](../../packages/io/src/get_flow_fields.f90#L226)), and
the meteo wind is read only if it is 0
([swan_tot.f90](../../packages/manager/src/swan_tot.f90#L178)). The
`useflowdata` flag also ignores a wind selection when meteofiles are present,
so wind alone does not make D-Waves read the com-file
([swan_input.f90](../../packages/data/src/swan_input.f90#L2077)).

## Parallel execution

Parallelism in the standalone pathway concerns D-Waves and SWAN only. The
hydrodynamic run that produced the com-files is finished, so whether it was
parallel does not affect how D-Waves runs; it only determines how many
com-files D-Waves has to read as input:

- **Delft3D4:** one or more runids listed in `[General] ComFile` (or the
  D-Waves runid), each read as a separate com-file
  ([flow_data.f90](../../packages/data/src/flow_data.f90#L99)).
- **D-Flow FM:** the file named in `[Output] COMFile`, or its numbered
  partition files (`..._0000_com.nc`, `..._0001_com.nc`, ...), which are
  detected by `checkcomfiles`
  ([flow_data.f90](../../packages/data/src/flow_data.f90#L84)).

D-Waves handles the SWAN grids and nests sequentially, in the configured
order; nesting is not MPI decomposition. How SWAN is executed is selected by
`SwanMode` ([swan_input.f90](../../packages/data/src/swan_input.f90#L829)):

- **`exe` (default):** SWAN is launched as a separate executable through a
  script.
- **`lib`:** requires an MPI-enabled D-Waves run. The D-Waves master handles
  mapping and file I/O and calls SWAN collectively with the other D-Waves
  ranks ([run_swan.f90](../../packages/kernel/src/run_swan.f90#L90)). Workers
  wait for SWAN commands and synchronize before the master reads and deletes
  the SWAN files ([run_swan_slave.f90](../../packages/kernel/src/run_swan_slave.f90#L53)).
